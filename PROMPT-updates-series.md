# gunco · ТЗ: серия обновлений (дефолты задачи, дизайн списка, дефолтный проект, кнопки удаления, чек-листы, нумерованные списки)

## 1. Убрать дефолтное время у новой задачи (дата остаётся «завтра»)
- **Дата по-прежнему по умолчанию = завтра** (не менять).
- **Время по умолчанию НЕ назначается** — убрать дефолт `12:00`. Время появляется и показывается (и на главной, и в карточке) только если задано вручную.
- Код: `newTask()` — `cardTime = ""` (сейчас `"12:00"`); `cardDate = tomorrowStr()` оставить.
- Так как дата всегда есть, задачи не собираются в блоке «без дня».

## 2. Уведомление по умолчанию выключено
- Сейчас `cardNotify = true`. Сделать **по умолчанию выключено** (`cardNotify = false`).
- Даже когда пользователь задаёт время, уведомление остаётся выключенным, пока он не нажмёт кнопку-колокольчик. `remind_at` ставится только при `notify && date && time` (логика уже есть в `updateTaskDateTime`).

## 3. Дизайн строки задачи на главной + логика времени уведомления
**Отображение (список задач):**
- **Убрать прочерк «—»** в колонке времени. Если времени нет — поле пустое.
- Если время задано — показать время.
- **Колокольчик** (тот же значок `BELL_ON`) показывается **всегда, когда у задачи включено уведомление** — независимо от того, задано время или нет. Если уведомление выключено — колокольчика нет.
- Варианты правой части строки: `пусто` / `12:00` / `🔔` / `12:00 🔔`. Колокольчик — справа (на месте/правее времени).
- Код: `taskRow()` — при отсутствии времени пусто (не «—»); колокольчик рисуется при `t.notify` вне зависимости от `t.due_time`.

**Когда приходит уведомление (логика `remind_at`):**
- Уведомление включено **и есть дата, и есть время** → приходит в это время.
- Уведомление включено, **есть дата, времени нет** → приходит в **11:00** этого дня.
- **Нет даты** (и времени) → уведомление не приходит, даже если тумблер включён.
- Код: `updateTaskDateTime()` — сейчас `remind_at` ставится только при `notify && date && time`. Заменить: `if (notify && date) { remind_at = date + "T" + (time || "11:00") }`, иначе `remind_at = null`. Edge-функция `send-reminders` не меняется (читает `remind_at`).

## 4. Дефолтный проект новой задачи = первый в списке проектов
- При создании задачи по умолчанию назначать **проект, стоящий первым в окне выбора проекта** (это `orderedProjects()[0]` — первая карточка в порядке канбана). Не «пустой проект».
- Пользователь ставит нужный проект («Текучка») первым в списке — и он назначается по умолчанию. Переставит другой первым — назначаться будет тот.
- **Важно (иммутабельность):** дефолт применяется в момент создания и сохраняется в задаче (`project_id`). Если потом изменить порядок проектов — у уже созданных задач проект НЕ меняется. Что назначилось при создании — то и остаётся.
- Исключение: если задача создаётся из карточки проекта (`newTask({projectId})`) — берётся этот проект, а не дефолтный.
- Если проектов нет вообще — проект пустой.
- Код: `newTask()` — `cardProjectId = opts.projectId || (orderedProjects()[0] && orderedProjects()[0].id) || null`.

## 5. Кнопки «Удалить» — тёмно-красный текст
- У всех кнопок «Удалить» на карточках задач и проектов (и во всех аналогичных местах, где есть «Удалить», — заметки, подтверждение удаления, удаление статуса) **фон и форму оставить прежними**, а **цвет текста «Удалить» сделать тёмно-красным** (например `#a01919`).
- Код: правило `.btn--danger` — задать `color: #a01919`. Проверить, что охвачены все кнопки удаления (в т.ч. в модалке подтверждения `askConfirm`).

## 6. Чек-листы: продолжение и выход по Enter (единая базовая механика)
Действует в **описаниях задачи и проекта и в теле заметки** (`#t-desc`, `#p-desc`, `#n-body` — сейчас `initChecklist`).
- Триггер создания чек-бокса остаётся прежним (ввод `[] ` в начале строки → строка становится чек-боксом).
- **Enter в конце строки-чекбокса, если в строке есть текст** (≥1 символа справа от чекбокса) → перенос строки и **новый пустой чек-бокс** ниже. И так до бесконечности.
- **Enter на пустом чек-боксе** (только что появился новый чек-бокс, текст не введён) при повторном Enter → **чек-бокс исчезает**, курсор переходит на обычную строку без отступа, дальше — обычный текст.
- Это стандартное поведение чек-листов (как в Notes/Todoist и т.п.).
- Обрабатывать `keydown` Enter внутри редактируемой области; определять, курсор в строке-чекбоксе или нет, пустая ли она.

## 7. Нумерованные списки
Действует в тех же трёх редактируемых областях.
- **Триггер:** в **самом начале строки** введено `число + точка` без пробелов (например `1.`, `22.`, `7.`) → строка превращается в пункт **нумерованного списка**.
  - Число может быть любым (не обязательно 1) и любой длины; список начинается с этого числа.
  - Если `число.` идёт **не в начале строки** (даже один пробел слева) — список НЕ создаётся, остаётся обычный текст.
- **Оформление:** пункт списка сдвинут влево на **один tab (≈5 символов)** отступа; последующие пункты идут с тем же отступом.
- **Enter в конце строки нумерованного списка** → список продолжается, **номер увеличивается на 1** (следующее число).
- **Enter на пустом пункте** (появилось новое число, текст не введён) при повторном Enter → **нумерованный список заканчивается**, дальше обычный текст без отступа.
- Нумерация ведётся в пределах непрерывного блока нумерованных строк; при продолжении — предыдущий номер + 1.

## Общие требования
- **Переиспользовать** существующее: `renderCardMeta`/`taskRow`/`newTask`/`orderedProjects`, `initChecklist`/`initFormatting`, `descSerialize`/`sanitizeHTML`, `.btn--danger`, значок `BELL_ON`.
- **Персистентность:** нумерованные списки должны сохраняться и восстанавливаться (расширить белый список санитайзера — сохранять узлы чек-листа и нумерованного списка с их атрибутами/отступом; всё так же чистить цвет/лишние стили). Проверить round-trip после перезагрузки.
- Всё работает и на десктопе (мышь/enter), и на телефоне (экранная клавиатура/ввод), в обеих темах.

## Критерии приёмки (чеклист)
1. Новая задача: дата = завтра, время пустое, уведомление выключено.
2. Прочерка «—» нет; время показывается только когда задано вручную.
3. Колокольчик в списке показывается всегда при включённом уведомлении (с временем или без): `пусто` / `время` / `🔔` / `время + 🔔`. Уведомление: время+дата → в это время; дата без времени → в 11:00; без даты → не приходит.
4. Новая задача получает первый проект из списка; смена порядка проектов не меняет уже созданные задачи; создание из проекта берёт его проект.
5. Все кнопки «Удалить» — тёмно-красный текст, фон/форма прежние.
6. Чек-лист: Enter продолжает список; двойной Enter на пустом пункте выходит в обычный текст.
7. Нумерованный список: `N.` в начале строки создаёт список с любого числа и отступом; Enter продолжает (+1); двойной Enter на пустом пункте завершает; сохраняется после перезагрузки.
